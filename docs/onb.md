# ONB coverage

The library supports the standard ONB173, ONB179, ONB191, ONB233 and ONB431
domains through `dstu4145.ParamsByName("DSTU_ONB_173")` and the corresponding
named OIDs. `AllParams` now includes fifteen domains: ten PB and five ONB.
Existing PB names and OIDs are unchanged.

## Representation and supported paths

Arithmetic and the coordinates stored in `ec.Curve`/`ec.Point` use polynomial
basis. Each ONB curve has an immutable conversion matrix built from its public
normal-basis root; the inverse is computed by binary Gaussian elimination.
`Curve.DecodeField` and `EncodeField` cross this boundary and reject values
outside the field. Scalars and signature integers are never basis-converted.

ONB conversion applies to the B coefficient and public points, compression/expansion,
digest interpretation, the field product before signature truncation, and
cofactor shared-secret output. The A coefficient remains the integer 0 or 1.
Complete domain comparisons include the basis,
polynomial, coefficients, subgroup order, cofactor and generator. Matching only
field degree and order can silently serialize ONB as PB: some domains share both.

Supported application paths include named/complete explicit parameters,
little-endian GOST ONB PKCS#8, Key-6/PFX protection and import, certificate key
association, GOST CMS signing/verification, GOST CSR generation/verification and
GOST agreement/encryption. The zero-digest substitute is polynomial-basis one:
conversion occurs before the zero check, covered by independent zero-digest vectors.
PKCS#8 and certificate loaders reject an algorithm/basis mismatch. Embedded
certificates retain the usual discovery-only trust policy.

ONB Kupyna/Kalyna application profiles currently return explicit errors.
Their wire profiles require separate validation. Passing the
primitive tests does not enable arbitrary ONB degrees or nonstandard domains.
These routines do not claim constant-time operation or a completed security review.

## Independent evidence

Public domains and conversion roots come from
[Cryptonite](https://github.com/privat-it/cryptonite/tree/3618d340d22e27a6becf97d89c453f8e64068a39),
specifically `dstu4145_params_internal.c` and PKIX `aid.c`/`oids.h`.
The retained license is in [licenses/cryptonite.txt](licenses/cryptonite.txt).

- `pkg/ec/normal_basis_test.go` checks published conversion values from
  Cryptonite's `utest_dstu4145.c`, inverse maps, normal-basis squaring rotations,
  domain/subgroup order, and point compression including the zero-x point.
- `pkg/dstu4145/testdata/onb-operations-cryptonite.json` was generated by compiling
  that unmodified Cryptonite revision with Ubuntu GCC and invoking its public
  APIs. For all five curves it contains public points, compressed points,
  cofactor shared secrets and signatures. The public scalars are deliberately
  `d=2` and peer `d=7`; the public seed is bytes `00..27`. Cryptonite's PRNG
  also mixes the clock, so rerunning the original producer can change signature
  bytes. The new PB producer freezes that clock explicitly; see
  [primitive fixture reproduction](primitive-validation.md#reproduction).
- `TestONBCryptoniteOperations` verifies those signatures and reproduces them in
  Go with their recovered public nonce, as well as checking the independent
  points and shared secrets. `onb-zero-digest-cryptonite.json` covers the zero-digest
  fallback with the same public keys and source revision. These keys must never
  be used operationally.
- `TestONBApplicationRoundtrip` covers GOST CMS, dynamic/static encryption, PFX,
  explicit trust and rejection of unverified modern profiles. This is local
  integration evidence, separate from provider interoperability.
- GOST CSR checks use independent Cryptonite hashing/signature verification and
  OpenSSL request parsing; see [CSR evidence and limits](csr.md).

The attempted native check used IIT x86 `1.3.1.224`, SHA256
`475539dd6b01015e73cf3d143783c3f164c3f9db1e92e724c6f6493f086d9f4f`.
Verification with the synthetic explicit ONB certificates/CMS produced here
returned `EUVerifyDataInternalOnTimeEx` error 50 for all five curves. This does
not establish whether the remaining difference is the certificate encoding,
CMS profile or SDK coverage. IIT ONB compatibility is unresolved; it is not part
of the passing PB interoperability matrix. No real credentials were involved.

Further isolated diagnostics compare explicit/named parameters and separate
container inspection, certificate parsing, signing and verification. Key-info
and `EUParseCertificateEx` succeed for the tested ONB cases, while cryptographic
operations are not consistently successful and report native errors 50/51.
Using named parameters alone has not established reproducible interoperability.

`TestIITONBDiagnostic` is opt-in with `IIT_ONB_DIAGNOSTIC=1`. Its PB257 positive
control must pass, and parser/key-info failures or unrecognized native failures
fail the test. Known ONB rejections are recorded as diagnostic results; successful
native signatures must verify in Go. A completed diagnostic is not an ONB
interoperability pass. It uses an intentionally public full-width fixture scalar.

## Reproducing operation vectors

With a separate Cryptonite checkout at the pinned revision and a C compiler on
Linux, run from this repository root (the reference source is not a Go dependency):

```sh
ref=/path/to/cryptonite
test "$(git -C "$ref" rev-parse HEAD)" = 3618d340d22e27a6becf97d89c453f8e64068a39 || exit 1
cc -O2 -DCRYPTONITE_EXPORT=extern \
  -I"$ref/src/cryptonite/c" -I"$ref/src/pthread/c" \
  "$ref"/src/cryptonite/c/*.c "$ref"/src/pthread/c/pthread_impl.c \
  pkg/dstu4145/testdata/generate-onb-vectors.c -pthread -lm -o /tmp/onb-vectors
/tmp/onb-vectors > /tmp/onb-operations.json
/tmp/onb-vectors zero > /tmp/onb-zero-digest.json
go test ./pkg/ec ./pkg/dstu4145 ./ua -run 'TestONB' -v
```

Compare decoded JSON fields with the retained fixture; whitespace and property
order do not matter. Ordinary Go tests use the retained public data and require
neither Cryptonite, a C compiler, IIT nor network access.
